# 0.2.2 性能优化与验收

## 已调整的路径

- 书籍的封面底图、书脊和文字录制成 ui.Picture；动画复用绘制命令，只改变几何投影、动态光照和位置。内容、序号、书签或封面变化时才重建；组件销毁时释放资源。
- 书籍封面最大按 512 像素宽解码；漫画正文不受这个封面限制影响。相同封面的读取不再跟随布局依赖重复发生。
- 封面取色在 32 × 32 缩略图上读取像素，缓存最多 48 个颜色结果。缓存不保留图片句柄；采样使用的临时图片和画布会释放。
- 只有访问过的页面才创建，切走后保留其场景与选书位置，停止不可见页的 tick/绘制。发现页换源时使用新状态，避免保留旧来源结果。
- 当前页由 RepaintBoundary 隔离，切页使用平移与淡入，不再对整页做变化中的模糊。
- 高级设置分组通过 SliverList 按滚动位置创建，首次打开不再一次性布局整页选项。
- 底栏保留真实背景模糊；玻璃底板与移动的选中块分层，镜片动画不再每帧重建和缩放整个滤镜。
- 大幅模糊封面背景改为封面取色后的柔和色场，保留环境色过渡；正文滚动仍会透过底栏的真实毛玻璃。
- Android 测试包改用 Profile/AOT；开发调试可运行 tools/Build-Android.ps1 -Debug，正式签名发行使用 -Release。Profile 不等于真机帧率已通过。

## 测量方法

本机浏览器 release 构建、390 × 844 逻辑视口，辅助语义开启，封面资源已加载。连续点四次“下一本”，每次留 600 ms；进入设置并返回书架，各留 700 ms。Chrome tracing 记录渲染器主线程 BeginMainFrame 时长。

初始 0.2.1：P50 7.567 ms、P95 17.299 ms、最大 80.853 ms；348 个主线程帧工作样本，21 个超过 16.67 ms，2 个超过 50 ms。

最终提交 f1de1b0 的测量结果：

| 场景 | P50 / ms | P95 / ms | 最大 / ms | 超过 50 ms |
|---|---:|---:|---:|---:|
| 0.2.1 初次进入设置 | 7.567 | 17.299 | 80.853 | 2 |
| 0.2.2 初次进入设置 | 6.808 | 12.204 | 59.560 | 1 |
| 0.2.2 已访问页面后重复 | 6.188 | 10.780 | 26.107 | 0 |

初次设置场景仍未通过严格的 50 ms 长帧检查，不能宣称已完全消除卡顿；保留这个失败结果。已访问页面后的重复操作通过检查。前两行是相同冷访问流程；第三行单独列出热状态，不拿它和第一行计算提升比例。不同采样次数受调度影响，不将帧数量直接换算为 FPS。

复核工具：python tools/analyze-performance.py .qa/perf-before.json --check。原始 trace 保存在本机 .qa，不提交浏览器记录。--check 按 P95 不超过 16.67 ms、没有超过 50 ms 的主线程帧工作做检查。

这些是当前机器与固定交互下的浏览器主线程测量，包含 tracing 开销；它们不能替代 GPU 呈现帧率、Android 真机、滚动长漫画或不同档位设备的测试。保留前后原始结果，不能把不同配置的数字混成一个 FPS 提升比例。
